# js/rules — Thousandvale's combat core (stream C)

Every number in a Thousandvale fight comes from **Farhold's own code**, imported unchanged. This folder
holds the parts that could not be imported — the orchestration inside Farhold's `main.js` closure and
`actors.js` (Three.js and HUD code mixed in) — forked over plain `{x, z}` positions, plus what an MMO
adds: rooms, a threat table, party targeting, Tab targeting.

Pure and server-safe: no Three.js, DOM, storage, fetch, `Math.random`, `Date.now` or timers. `boot.js` is
the one exception, and it only reads the data files once at load. `tests/C/purity.test.mjs` enforces this.
It runs the same under Node (server), in a Web Worker (offline play) and on the client.

## Using it outside the room

```js
import { createEngine } from './engine.js';           // data from loadRulesData(readJson)
import { createRoomContext } from './room.js';
import { attachField } from './field.js';
import { createCombat } from './cast.js';
const room = createRoomContext({ id: 'r1', seed: 7, engine });
attachField(room, { terrain });
room.combat = createCombat(room);
room.run(() => room.combat.attack(ch, { yaw }));      // ALWAYS inside room.run
```

## What the MMO changes (PLAN §6.2)

- **Threat**: damage ×`threatMult`. Healing adds 50%, split across the monsters already fighting whoever was healed. A taunt forces the target and lifts the taunter to 110% of the top. A monster only switches targets when someone passes 110% of its current target's threat (melee) or 130% (ranged).
- **Allies** = the caster's own followers (anywhere in the room, as in Farhold) plus party members (`partyId`) and their pets **within 30 m** (`ALLY_RANGE`). See "Ally targeting" below.
- **Leash**: 40 m from home, or 8 s with no damage dealt or taken while out of reach of its target (walking a path that reaches it, and getting closer along it, counts as progress). Either one sends the monster home to heal, along a path round walls; one that has not made it home in 12 s is put back. It doesn't think at all when nothing friendly is within 200 m.
- **Pathfinding** (`pathfind.js`): on a baked zone monsters go round walls, buildings, trees, cliffs and deep water. Budget: 4,000 expansions per room per tick (≈2 ms worst case), measured 0.2 ms mean for 100 hounds in a maze (tests/C/pathfind).
- **Province scale (A's M2)**: monsters with no player within 200 m sleep (`e.asleep`) and are skipped by the push-apart pass and by `syncOut` after one last sync; the nearest player comes from a 200 m bucket grid built once a tick; "monsters near this point" (a player's fighting flag, a follower looking for prey) reads a 24 m monster index rebuilt once a tick (`field.eachMonsterNear`). Strikes still walk the list in order, because their dice depend on it. 1,300 monsters + 70 players: rules step 1.6 ms mean (tests/C/province-rules); A's bots100 spread phase p99 7.0 ms.
- **Perf pass (2026-10-05, A's 100-bot gate red after E's denser content)**: profiled (`node --cpu-prof` on tests/A/bots100) — the worst ticks were not the monster brain but (1) a level-up's build view writing ~70 talent cards through `toLocaleString` (up to 38 ms in one tick: `talents.js nodeText` is now cached per row/node), and (2) a monster's first path into fresh ground working out ~3,000 cells × 5 terrain samples (15 ms in one tick: a first-time cell now costs budget like an expansion — `PATH.EVAL_COST` — so the search spreads over ticks, and the slope/water test is taken once per cell, the cheap obstacle test still at five points). Plus monster LOD in rooms (`field.lod`, never the parity fixtures): a wanderer with nobody within 70 m, nothing on it and no awake band thinks every 4th tick on its own phase with the time it skipped (1,400 idle awake monsters: 1.84 -> 1.10 ms a tick). Spread phase: p99 22 -> 11.4-11.7 ms, worst 37.5 -> 18-21 ms; rules step per tick p99 8.1 -> 5.4 ms, max 42 -> 6.7 ms.
- **Rares on a loop**: a monster spawned with `data.path` walks it at a stroll when not fighting (round walls), its leash home riding along. **Event bosses**: `data.scale` multiplies health.
- **Taken away without dying** (a parked camp, `room.remove`): no death, no reward, no corpse; followers drop it, links to it break, a delayed strike or DoT holding it can no longer kill it.
- **Skill bar for the client**: `rules.bar(e)` → `[{slot 1..6, id, name, desc, cd (ms), mp, level, locked, empty, shape, element, ally, group, charges, form}]` — Farhold's live bar, so talents/forms/stances show.
- **Party calls**: a non-companion `command` (focus/pounce/return) is also heard by party members' followers within 30 m; `empowerNext.pets` puts the rider on each party member's own next skill (`mech.empower`, the slot their bar spends).
- **Rewards**: everyone who did damage gets XP, gold and their own loot roll (a party gets one roll per corpse when the room offers `host.partyLoot`, play-test 2 Q4). In a room these go to `host.award` and a `loot` event.

### Build: talents and perks (the room's API, A and D)

- `rules.talents(e)` -> `{ tiers: [3,8,18,28], level, skills: [{ slot, skillId, name, shape, element, open, unlockAt, tiers: [{ tier, level, open, picked, nodes: [{ id, name, desc, fx, bespoke, requires, picked }] }] }] }` — the talent screen.
- `rules.pickTalent(e, skillId, tier, nodeId)` / `rules.unpickTalent(e, skillId, tier)` / `rules.resetTalents(e, skillId?)` -> `{ ok, bar, build }` or `{ ok: false, text }`. A pick into an empty tier is free; emptying one is the Unbinder's (A charges `rules.retrainPrice(e, 'talent', 'one'|'all')` first — Farhold's `balance.retrain`).
- `rules.perkForest()` -> `{ arms, nodes: [{ id, kind, label (show this: 'Cornerstone' for a keystone — the word keystone is banned in player-facing text), arm, ring, branch, x, y, name, desc, cost, when, oddball, rule }], links, start }` — static per process (cache it). `rules.perks(e)` -> `{ total, spent, left, taken, flags }`.
- `rules.takePerk(e, id)` / `rules.refundPerk(e, id)` (an END of a walk only) / `rules.resetPerks(e)` -> `{ ok, bar, build }`; A charges `retrainPrice(e, 'perk', …)` for a refund.
- `rules.saveBuild(e)` -> `{ v: 1, talents, perks, bonusPerks, unlocks }`: A saves it as `char.build`; `addEntity` restores it (picks that no longer exist and perks that no longer connect are dropped). `bonusPerks` is where a quest's perk point goes.
- After any change the rules call `host.barChanged(e)` (if the room has it) and emit `fx kind:'build'` — the bar's slots, costs, cooldowns and `talents` (picked names) may have moved, and the sheet was re-derived.
- `bar(e)` entries gained `talents: [names]`.
- **A's message contract** (docs/protocol.md §17.2), wired to the above: `rules.talent(e, 'pick'|'clear', { skill, tier, node })` -> `{ ok, why?, text?, picks, talents }` (`clear` with a tier empties that tier, without one the whole skill); `rules.perk(e, 'take'|'refund'|'reset', { id })` -> `{ ok, why?, text?, perks, left }`; `rules.build(e)` -> `{ talents, perks, perkPoints: {total, spent, left}, talentTree, companion }`. `why` codes: level, taken, points, connect, needed, unknown.

## Ally targeting (PLAN §6.2; audited for all 30 classes)

The client sends a friendly `target` with the cast (Tab target or a party frame). What happens:

| What the plan does | Who gets it |
|---|---|
| a heal on a `self` skill (Mend, Inner Stillness, Pocket Watch…) | the targeted ally (sized to *their* health), else you |
| a mend over time (`status: 'regen'`, Greensap) | the targeted ally, plus your followers (Farhold mends them with you) |
| "you and every follower" (`pets: true`: Quicken, Rally, Foresight, Warding Spirits, Martyr's Vow, Unbroken Banner, the group selfBuffs) | you, every party member within 30 m, and your followers |
| any other status or selfBuff (War Cry's Might, stances, tempers, counters, Overchannel…) | **you** — a personal buff never moves to a friend |

| a cleanse | the targeted ally; with `pets` also the rest of the group |
| `healPets` (group heal), `burst.heal`, `healAllies`, a placed zone's heal/buff, a song's aura | every party member in reach (radius, else 30 m) and your followers |

| `link` (Sworn Ward, Sworn Guard, Thread of Fate) | the targeted ally, else the nearest party member/follower |

| `command` without `petOnly` (focus / pounce / return) | your followers and the party's followers within 30 m (players are never ordered) |
| a form's onEnter / finale (cast with no target) | group effects only; a stance's own barrier/ward is personal |

## Farhold findings (left as they are in Farhold; reported to the lead)

1. **Stealth never worked.** `EnemyField.update(dt, player, …)` is handed the *controller* as `player`, and the notice range reads `player.derived.stealth`, which is always undefined, so every cloak's stealth does nothing. Thousandvale reads the real sheet, so stealth works here.
2. **The staff's charged "mortar" does nothing extra.** main.js gives it a 1.4× radius and a 3 s ground pool, then throws it through `fireBolt`, which reads neither. We copy this exactly for parity.
3. **A melee skill borrows the last basic swing's shape** (`feel.swing.strike`): that weapon's traits, armour pierce, and its knockback when the skill has none of its own. Thousandvale keeps this per player (`ch.lastStrike`).
4. **One shared world for traps, walls and corpses** (skillmech `world`) is what `room.js` exists to split. The parity oracle has to `mech.reset()` between fixtures, because otherwise one fixture's Rampart still stands in the next.
